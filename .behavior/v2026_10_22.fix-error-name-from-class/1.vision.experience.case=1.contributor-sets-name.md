# case 1 — a contributor sets `name`

sharp · critipath · actor: contributor to helpful-errors · class: all three

## narrative

a contributor reads a lambda log where a ConstraintError shows `errorType: 'Error'`. it looks like a one-line fix, so they add `this.name = new.target.name` to the `HelpfulError` constructor and run the suite. `HelpfulError.name.test.ts` goes red for every class: `name` is no longer `'Error'`, the instance carries an own `name`, and json gains a `name` key. its header points at `rule.forbid.error-name-override.md`, which says the question is settled, why, and that the fix belongs where the consumer classifies. the contributor reverts the line and takes the log to the producer that should classify.

## bdd

- `[t0]` given a contributor adds `this.name = new.target.name` to the constructor
  - when the unit suite runs
  - then `HelpfulError.name.test.ts` fails for the base, each built-in, and the consumer subclass
- `[t1]` given a contributor instead defines a `name` accessor on `HelpfulError.prototype`
  - when the unit suite runs
  - then the test `should define no name on any prototype in its chain` fails
- `[t2]` given a contributor adds `name` to `toJSON`
  - when the unit suite runs
  - then the test `should keep name out of json output` fails
- `[t3]` given the clamp fails
  - when the contributor reads the test header
  - then it names `rule.forbid.error-name-override.md`, whose `.settled` section records the case and the decision

# case 4 — a consumer switches on `error.name`

sharp · critipath · actor: consumer who switches on `name` · class: all three

## narrative

a consumer writes `if (error.name === 'ConstraintError') return 400;`. the branch never fires, because `name` reads `'Error'` for every HelpfulError, so a caller fault falls through to a 500. they file an issue that asks helpful-errors to set `name`. the reply cites the readme `.name` note and `rule.forbid.error-name-override.md`: a switch on `error.name` is the code smell, and the fix is `instanceof` in process or the producer's deliberate field across a wire.

## bdd

- `[t0]` given a consumer branch `error.name === 'ConstraintError'`
  - when a ConstraintError is thrown
  - then the branch does not fire
- `[t1]` given the consumer asks helpful-errors to set `name`
  - when a maintainer reads the rule
  - then the request is named a code smell, with the fix table for the consumer
- `[t2]` given the consumer moves to `error instanceof ConstraintError`
  - when a ConstraintError or any subclass is thrown
  - then the branch fires

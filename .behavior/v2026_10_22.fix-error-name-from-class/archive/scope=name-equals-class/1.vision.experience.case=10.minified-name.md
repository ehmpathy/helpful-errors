# case=10 — minified bundle mangles the class name

feel: sharp · care: alterpath

## narrative

a lambda is bundled with esbuild `--minify` and no `--keep-names`. the bundler renames `ConstraintError` to a short identifier, so `new.target.name` reads, say, `'t'`. the wire reads `errorType: 't'`, a server fault — the original defect, by another route.

## freq × cost

- freq: low. the message prefix already reads `new.target.name` (`src/HelpfulError.ts:92-97`), so a mangled bundle already prints `✋ t: …` today — a visible tell any engineer who reads the logs would have flagged. no such report exists against this repo
- cost: bounded, with a workable route around it — add `--keep-names` (esbuild, terser `keep_classnames`), a one-flag build fix. the wire then reads the true class
- ⇒ alterpath: a real route exists, and it is cheap

## fail-safe

- loud: the mangled name shows in every log header and message prefix, so the cause is visible in the first log line
- teaches the fix: the PR body notes that `name` reads `Function.name`, so a minified bundle needs `--keep-names`
- a hardcoded per-class name would cover built-ins only and miss user subclasses (fulcrum F4)

## [tn] timeline

- [t0] given a lambda bundled with `--minify` and no `--keep-names`
- [t1] when it throws a `ConstraintError`
  - then `errorType` and the log header read the mangled name
- [t2] when the bundle adds `--keep-names`
  - then `errorType` = `'ConstraintError'`

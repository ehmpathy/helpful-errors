# case=8 — user subclass of a caller-fault class on the wire

feel: sharp · care: critipath

## narrative

svc-quotes declares `class QuoteExpiredError extends ConstraintError {}` and throws it from a lambda. after the fix, the wire reads `errorType: 'QuoteExpiredError'` — its true class, as the wish requires ("any user subclass"). but sdk-aws-lambda maps only the exact names `ConstraintError` | `BadRequestError` to a caller fault. `QuoteExpiredError` is not in that map, so the client still reads a server fault, and sqs still retries.

this is **not a regression**: before the fix the same throw read `errorType: 'Error'`, also a server fault. the fix moves the wire from "no class at all" to "the true class"; it cannot, by itself, tell a client across the wire that `QuoteExpiredError` is-a `ConstraintError` — the wire carries a string, not a prototype chain.

what the wire does carry, after the fix, is enough for the client to classify:
- `errorType: 'QuoteExpiredError'` — the true class
- `errorMessage: '✋ QuoteExpiredError: …'` — the `✋` glyph is `ConstraintError.emoji`, a static that the subclass inherits (`src/HelpfulError.ts:87-88`), so the caller-fault marker survives in every subclass

## fail-safe

- loud: the caller-fault marker survives on the wire. `errorMessage` opens with `✋ QuoteExpiredError:` — the inherited `ConstraintError.emoji` — so every wire payload and log line shows a caller fault to a human, and gives a classifier a stable key
- teaches the fix: the PR body names the gap and the glyph key, so the sdk-aws-lambda#73 author can classify on it
- bounded: no worse than before the fix (`errorType: 'Error'`, also a server fault)

## deferred route — not a current fail-safe

- sdk-aws-lambda#73 classifies by the inherited `✋` glyph, or accepts a declared allowlist of caller-fault names. code in another repo; caught as a reseed dream from this route (`dreams/`)

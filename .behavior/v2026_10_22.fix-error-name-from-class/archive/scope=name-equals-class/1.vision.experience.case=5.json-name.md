# case=5 — engineer queries json logs by name

feel: happy · care: critipath

## narrative

an engineer chases a spike of rejected quotes. they open the log store and filter on `name = ConstraintError`. before the fix, no row carried a `name`, so they regex'd the message for `ConstraintError:`. now each row carries `"name":"ConstraintError"` beside `message` and `stack`, the filter returns the spike in one query, and the engineer moves on to the cause.

## [tn] timeline

- [t0] given a service that logs `JSON.stringify(error)` for `new ConstraintError('validation failed', { field: 'email' })`
- [t1] when the engineer filters the log store on `name = ConstraintError`
  - then the row matches: the json has key `name` = `'ConstraintError'`
  - then `message`, `stack`, and `code` (when slug present) read as before
  - then `Object.keys(error)` stays `[]` — `name` is non-enumerable (fulcrum F1); the json carries it via `toJSON`

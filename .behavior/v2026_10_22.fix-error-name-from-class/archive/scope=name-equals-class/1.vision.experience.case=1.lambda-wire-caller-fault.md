# case=1 — lambda wire reads a caller fault

feel: happy · care: critipath · densest

## narrative

a svc-quotes lambda receives a quote request with no provider. it runs `ConstraintError.throw('quote lacks provider', { quoteUuid })`. the aws node runtime serializes the throw as `{ errorType: error.name, errorMessage: error.message }`. today `errorType` reads `Error`, so sdk-aws-lambda calls it a server fault and sqs retries a request that can never pass. after the fix, `errorType` reads `ConstraintError`; the client classifies a caller fault and the message lands once, as a failure the caller owns.

## [tn] timeline

- [t0] given a handler that throws `ConstraintError.throw('quote lacks provider')`
- [t1] when the runtime serializes the throw
  - then `errorType` = `'ConstraintError'` (was `'Error'`)
  - then `errorMessage` = `'✋ ConstraintError: quote lacks provider …'` (unchanged)
- [t2] when sdk-aws-lambda maps the wire error (sdk-aws-lambda#73)
  - then it maps a caller fault, so sqs does not retry
- the same holds for `BadRequestError` → `'BadRequestError'`, `MalfunctionError` → `'MalfunctionError'`, `UnexpectedCodePathError` → `'UnexpectedCodePathError'`

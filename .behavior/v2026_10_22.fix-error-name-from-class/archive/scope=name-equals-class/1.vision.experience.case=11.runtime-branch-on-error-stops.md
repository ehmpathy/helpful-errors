# case=11 — prod branch on `'Error'` stops to match

feel: sharp · care: critipath · happy twin: case 7

## narrative

a service author once wrote `if (error.name === 'Error')` as a catch-all for "an error from helpful-errors". after the upgrade that branch stops to match for HelpfulErrors, and the author's fallback path runs instead. this is the one place the fix changes prod behavior silently — no test fails unless one asserts on it.

## fail-safe

not fast, not loud — by nature: a string comparison that stops to match raises no signal, and a warn on every `name` read would spam every logger and the aws runtime. the mitigation is teach + findable, and the choice is fulcrum F5.

- teaches the fix: the PR body names the shift (`name` was `'Error'`, now the class) and points to `isHelpfulError` / `instanceof HelpfulError`, the documented detectors, which the fix leaves untouched (`src/isHelpfulError.ts`)
- findable: a consumer who greps their code for `name === 'Error'` at upgrade finds every such branch
- bounded: the branch relied on the defect — a value that named no class — and the wish ships this as a `fix`

## [tn] timeline

- [t0] given prod code `if (error.name === 'Error')` aimed at HelpfulErrors
- [t1] when a `ConstraintError` is caught after the upgrade
  - then the branch no longer matches
  - then `isHelpfulError(error)` still returns `true`
- [t2] when the author reads the PR body and switches the branch to `isHelpfulError(error)`
  - then the branch matches again, for every HelpfulError class

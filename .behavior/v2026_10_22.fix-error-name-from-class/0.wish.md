# wish: a HelpfulError carries its class name as .name

## .the defect

ehmpathy/helpful-errors#45. helpful-errors never sets `this.name`, so `new ConstraintError(...).name === 'Error'`. the aws node runtime serializes a thrown error as `errorType: error.name`, so a ConstraintError thrown in a lambda reaches the wire as `errorType: 'Error'`. sdk-aws-lambda's client maps only `ConstraintError` | `BadRequestError` to a caller fault, so a caller fault reads as a server fault and sqs retries it (svc-quotes prep acceptance, run 38852404042).

## .the outcome

- every HelpfulError subclass (ConstraintError, MalfunctionError, BadRequestError, UnexpectedCodePathError, and any user subclass) carries `.name` equal to its own class name, set once in the `HelpfulError` constructor (e.g. `this.name = new.target.name`)
- `String(error)` and the stack header read the class name too

## .done

1. a clamp per built-in subclass and one user-defined subclass: `.name` equals the class name. red before the fix, green after
2. a clamp: `JSON`/wire-shaped serialization of `{ errorType: error.name }` reads `ConstraintError` for a thrown ConstraintError
3. every extant snapshot that pins the old `Error` name is updated, each change named in the PR body
4. a PR on ehmpathy/helpful-errors, CI green, every stone passed, for the commander's review. no merge, no `--apply`
5. the PR body and every commit carry no "Generated with Claude Code" footer and no "Co-Authored-By: Claude" trailer

## amendment, 2026-10-22 — the scope is reversed

the outcome above is overturned. **helpful-errors leaves `error.name` alone; it adds a rule that forbids any override, and a test that clamps it.**

### the new outcome

- `error.name` stays the native `'Error'` on HelpfulError and every subclass. no constructor stamp, no prototype accessor, no `toJSON` entry
- `.agent/repo=.this/role=any/briefs/rule.forbid.error-name-override.md` forbids any change that sets or shadows `name`, names a switch on `error.name` as a code smell, and records why
- `src/HelpfulError.name.test.ts` clamps the invariant for the base class, each built-in, and a consumer subclass: `name === 'Error'`, no own `name`, no `name` on any class prototype, none in json
- the readme states it: tell the class via `instanceof` or `isHelpfulError`, never `name`

### the new done

1. the clamp is red when any route sets `name`, green otherwise
2. the rule records the overturned case and where it was settled, so it is not reopened
3. no extant snapshot changes
4. a PR on ehmpathy/helpful-errors, CI green, every stone passed, for the commander's review. no merge, no `--apply`
5. no "Generated with Claude Code" footer and no "Co-Authored-By: Claude" trailer, in the PR body or any commit

### where it was settled

- the human, in this route's session on 2026-10-22: the class already leads the message, so a set `name` only repeats it — every rendered error reads `ConstraintError: ✋ ConstraintError: …` — and no use case needs `name` pinned. a switch on `error.name` is the defect
- the director's why-check, same day, confirmed it from the peer branch `ehmpathy/sdk-aws-lambda@beav/fix-local-locus-reads-error-name`: `genConstraintErrorMiddleware` classifies by class and writes a deliberate `errorType` at the producer, so the wire never needs `name`. the requirement behind #45 was itself the defect
- shipped as ehmpathy/helpful-errors#47; #46, which set `name`, is closed
